# 实施计划

## 执行原则
按阶段推进。每阶段完成后先运行测试、检查 Git diff，再进入下一阶段。不要一次性让 Codex 实现所有阶段。

## Phase 0 — 仓库检查与工程骨架
- 检查空仓库/现有仓库，确定是否保留已有文件。
- 建立 backend、frontend、docs、scripts 基础结构。
- 建立配置读取、健康检查、统一错误响应。
- 配置 Python 依赖、前端 package、格式化/lint/test 命令。
验收：后端可启动并返回 live/ready；前端可启动；基础测试通过。

## Phase 1 — 数据库和牌库
- SQLAlchemy 模型与 Alembic。
- users、tarot_cards、spreads、readings、reading_cards、chat_messages、agent_runs。
- 创建可追溯的牌库数据源说明。
- 编写幂等 seed 脚本。
- 录入完整 78 张牌和四种初始牌阵。
验收：数据库迁移成功；牌库数量和分类测试通过；重复 seed 不破坏数据。

## Phase 2 — 牌库/牌阵 API 与前端
- 查询牌库、详情、过滤和分页。
- 牌阵列表与详情。
- 前端首页、牌库页、牌详情、牌阵选择页。
验收：API 测试、前端组件测试通过；无 AI 时可浏览资料。

## Phase 3 — 认证与抽牌
- 注册、登录、退出、me。
- 密码哈希、统一认证模式和对象权限依赖。
- 抽牌服务、Reading 创建、牌面快照、幂等策略。
- 问题输入和抽牌展示页面。
验收：抽牌数量正确、无重复牌、正逆位合法；权限测试通过。

## Phase 4 — 基础 AI 解读
- 定义模型适配器和配置验证。
- 定义 Pydantic 解读 Schema。
- 实现提示词和结构校验。
- 实现 interpret API、失败状态和重试。
- 完成解读展示页。
验收：使用 mock 测试成功、超时、错误 JSON；重试不重抽牌。

## Phase 5 — LangGraph 工作流
- 定义 state、节点、条件边和错误路径。
- 加载快照、构建上下文、生成解读、校验、有限修复、保存结果。
- 记录 run_id、模型名、提示词版本、状态和错误码。
验收：图工作流成功/失败/修复失败分支均有测试。

## Phase 6 — RAG
- 选择合法资料并登记来源、许可和版本。
- 创建知识文档/切片模型及 pgvector migration。
- 实现导入、去重、Embedding、过滤和检索。
- 来源 ID 校验及引用展示。
- 建立至少 30 条评估集。
验收：引用只能指向检索到的来源；正逆位过滤测试通过。

## Phase 7 — 历史与多轮追问
- 历史列表、详情、筛选、删除。
- ChatMessage 持久化。
- 追问使用原 Reading 快照和有限上下文。
验收：越权测试通过；追问不重抽牌；历史可恢复。

## Phase 8 — 部署与端到端
- Dockerfile、Compose、Nginx、持久化卷和健康检查。
- 生产配置、安全头、限流和日志脱敏。
- Playwright 完整流程。
- 备份/恢复脚本与演练说明。
验收：干净环境按 README 启动；完整 E2E 通过；备份可恢复。

## 每阶段结束时
1. 查看 Git diff。
2. 运行该阶段测试。
3. 更新 README 和阶段状态。
4. 明确列出未实现事项。
5. 只有满足验收条件才标记阶段完成。
