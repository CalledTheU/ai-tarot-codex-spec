# 实施计划

## 执行原则
按阶段推进。每阶段完成后先运行测试、检查 Git diff，再进入下一阶段。不要一次性让 Codex 实现所有阶段。

## Phase 0 — 仓库检查与工程骨架
- 检查空仓库/现有仓库，确定是否保留已有文件。
- 建立 backend、frontend、docs、scripts 基础结构。
- 建立配置读取、健康检查、统一错误响应。
- 配置 Python 依赖、前端 package、格式化/lint/test 命令。
验收：后端可启动并返回 live/ready；前端可启动；基础测试通过。

状态（2026-10-29）：Phase 0 验收通过。保留并补齐现有骨架，已验证 Python 3.11.9、Node.js 24.19.0、npm 11.17.0 下的依赖安装、格式/lint/类型检查、后端 13 项测试、前端 1 项测试和构建。实际启动 Uvicorn 与 Vite 后，live/ready、前端首页及 React 模块 HTTP 检查通过。以上为 Phase 0 历史验收记录；后续阶段进度见下文。

## Phase 1 — 数据库和牌库
- SQLAlchemy 模型与 Alembic。
- users、tarot_cards、spreads、readings、reading_cards、chat_messages、agent_runs。
- 创建可追溯的牌库数据源说明。
- 编写幂等 seed 脚本。
- 录入完整 78 张牌和四种初始牌阵。
验收：数据库迁移成功；牌库数量和分类测试通过；重复 seed 不破坏数据。

状态（2026-10-29）：Phase 1 验收通过。真实 PostgreSQL 17.6 的隔离测试 schema 中，迁移往返、ORM 一致性、78 张来源摘录及四种牌阵、幂等与保留已有内容、数据库约束及级联删除测试均通过；连同配置和健康检查共 22 项通过。SQLite 辅助测试也通过。来源登记见 `data/tarot_sources.md`；牌义为经过源文件比对的英文历史摘录，未冒充已审核中文译文。Reading 采用物理删除与子记录外键级联策略，私有读写接口留待后续阶段。

## Phase 2 — 牌库/牌阵 API 与前端
- 查询牌库、详情、过滤和分页。
- 牌阵列表与详情。
- 前端首页、牌库页、牌详情、牌阵选择页。
验收：API 测试、前端组件测试通过；无 AI 时可浏览资料。

状态（2026-10-29）：Phase 2 验收通过（后端 48 项、前端 10 项及真实浏览器联调通过）。公开 cards/spreads 四个接口与前端首页、筛选分页、牌详情、牌阵选择和详情已实现；来源与历史文本边界在详情中展示，牌位由后端坐标与定义驱动。真实 PostgreSQL API 测试及 React Testing Library 组件测试、Edge 浏览器真实联调结果见 `docs/TESTING.md`。无需模型即可浏览资料；本次止于 Phase 2，Phase 3 尚未开始。

## Phase 3 — 认证与抽牌
- 注册、登录、退出、me。
- 密码哈希、统一认证模式和对象权限依赖。
- 抽牌服务、Reading 创建、牌面快照、幂等策略。
- 问题输入和抽牌展示页面。
验收：抽牌数量正确、无重复牌、正逆位合法；权限测试通过。

## Phase 4 — 基础 AI 解读
- 定义模型适配器和配置验证。
- 定义 Pydantic 解读 Schema。
- 实现提示词和结构校验。
- 实现 interpret API、失败状态和重试。
- 完成解读展示页。
验收：使用 mock 测试成功、超时、错误 JSON；重试不重抽牌。

## Phase 5 — LangGraph 工作流
- 定义 state、节点、条件边和错误路径。
- 加载快照、构建上下文、生成解读、校验、有限修复、保存结果。
- 记录 run_id、模型名、提示词版本、状态和错误码。
验收：图工作流成功/失败/修复失败分支均有测试。

## Phase 6 — RAG
- 选择合法资料并登记来源、许可和版本。
- 创建知识文档/切片模型及 pgvector migration。
- 实现导入、去重、Embedding、过滤和检索。
- 来源 ID 校验及引用展示。
- 建立至少 30 条评估集。
验收：引用只能指向检索到的来源；正逆位过滤测试通过。

## Phase 7 — 历史与多轮追问
- 历史列表、详情、筛选、删除。
- ChatMessage 持久化。
- 追问使用原 Reading 快照和有限上下文。
验收：越权测试通过；追问不重抽牌；历史可恢复。

## Phase 8 — 部署与端到端
- Dockerfile、Compose、Nginx、持久化卷和健康检查。
- 生产配置、安全头、限流和日志脱敏。
- Playwright 完整流程。
- 备份/恢复脚本与演练说明。
验收：干净环境按 README 启动；完整 E2E 通过；备份可恢复。

## 每阶段结束时
1. 查看 Git diff。
2. 运行该阶段测试。
3. 更新 README 和阶段状态。
4. 明确列出未实现事项。
5. 只有满足验收条件才标记阶段完成。
